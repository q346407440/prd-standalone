# PRD 规范（prd-spec）

> 写 PRD 时 `@prd-spec`。需要**文风、润色、待确认句式、变更用语、标题命名习惯**时，一并 `@prd-writing-style`（见 `.cursor/skills/prd-writing-style/SKILL.md`）。

---

## 零、角色与边界（最高优先级）

**当用户 `@prd-spec` 时，你进入 PRD 写作模式，必须遵守以下规则：**

1. **只读业务代码，不改业务代码**：为理解已实现功能，你可**只读**业务源码：**(a)** `../`（`prd-standalone` 嵌套在业务仓库内时，父目录为业务根）；**(b)** Cursor **多根工作区**内与用户 PRD 任务**并列、用户已关联**的其他项目根。结合用户 `@`、项目名或语义搜索定位。**绝不修改**业务项目任何文件。写入**仅限** `prd-standalone/`：
   - `pages/doc-NNN/*.md` — PRD 正文
   - `pages/doc-NNN/*.meta.json` — 展示元数据
   - `pages/doc-NNN/*.annotations.json` — 标注数据
   - `pages/doc-NNN/assets/` — **该文档专属截图（colocated）**，正文里写作 `./assets/xxx.png` 相对路径
   - `pages/.active-doc.json` — 激活文档索引（通过 API 操作）
   - `public/prd/` — 迁移期遗留旧截图（兼容期不再产生新文件，新增图一律落到上面 colocated 目录）
2. **不要修改项目配置与源码**：`src/`、`vite.config.js`、`package.json`、`.cursor/`、`feishu-sync-server.js` 等均不在写作范围内。
3. **不要把 PRD 内容写入业务代码**（含 `../` 或多根工作区内的关联仓库）。
4. **若用户要求改业务代码**：提醒其在**不携带** `@prd-spec` 的新对话中操作。

**仓库与业务路径（读 PRD / 读业务时对照）：**

- **嵌套**：`../` 常为业务根；**多根工作区**下业务代码在**其他根目录**，用 `@` / 搜索定位，**只读**。
- **多文档**：每文档 `pages/doc-NNN/`，同名的 `.md`、`.meta.json`、`.annotations.json`；激活 slug 在 `pages/.active-doc.json`。
- `pages/<slug>/<文档名>.md` 为正文唯一真相；`.meta.json` 仅展示用（图宽、Mermaid/Mindmap 视图等）；`annotations.json` 可选增强。
- **截图（colocated）**：每篇文档的截图存于 **`pages/<slug>/assets/`**，正文里写 **`![语义说明](./assets/xxx.png)`** 相对路径——Cursor 内可点跳转，与前端渲染 / 离线包 / 原生 MD 导出 / 飞书同步全链路一致。`public/prd/` 仅保留迁移期遗留旧引用，**禁止**新写。
- **磁盘存在性核对**：`pages/doc-*/`（含 colocated 截图）与 `public/prd/*.png` 都被 **`.gitignore` 整目录忽略**，**Glob / 仓库索引** 会**忽略**这些路径，**搜不到 ≠ 磁盘没有**。Agent **核对某张 PNG 是否存在**时：用 **只读** Shell `ls pages/<slug>/assets/`、`test -f pages/<slug>/assets/<文件名>.png`，或对**已知绝对路径** **Read**；**勿**仅凭「Glob 无结果」下结论。用户本机 PRD 站能加载 `./assets/xxx.png` → 一般等价于 **`pages/<slug>/assets/xxx.png` 存在**（dev 服务器把 `pages/<slug>/assets/` 暴露在 `/pages/<slug>/assets/`）。

## 〇·一、写 PRD 表格前合规清单（每次改表先过一遍）

动笔修改或新增三列表格（`设计/原型稿 | 交互 | 逻辑`）前**逐项确认**（细则见 **五、六、七**；**用语与文风**见 **prd-writing-style**；写完后可再扫一遍）：

1. **表格语法**：表格使用 **cell 标记格式**（`<!-- block:table cols="..." -->`、`<!-- cell:rN:列名 -->`），格内用**原生 Markdown**（段落空行分隔、列表直接 `- `、图片 **`![语义说明](...)`** 独立一行且**不带列表前缀**）。**禁止格内放 mermaid / mindmap**——脑图、时序图、流程图、逻辑图等**一律抽到表格外**作为顶层 `<!-- block:mermaid -->` / `<!-- block:mindmap -->`。**废除** GFM 管道行、`<br>` 换行、`:::mermaid:::`、独立 `<!-- row:N -->`。详见 **五 → cell 标记格式**、**六 → Mermaid 图表 block** 与 `prd-writing-guard.mdc`。
2. **列举子项必换行**：多条子项**每条单独成条**；**禁止**顿号、分号挤一行。交互列**禁止**写作元说明（润色见 **prd-writing-style**）。详见 **五 → 换行与子项列举**。
3. **hover / 说明气泡**：`交互` 列固定 **`- **【hover 文案】**：`** + 定稿全文（全角冒号在闭合 `**` 后）。**禁止**「说明（…）」括号全文。卡片内长说明用 **`**说明文案**`**，勿套【hover 文案】。详见 **五 → hover**。
4. **交互 / 逻辑换行密度**：**加粗区块** → 一级 `-` → 必要时 **`  - `**；逻辑列**禁止**分号串多条规则。详见 **五 → 换行与子项列举**。
5. **设计列**：以 **`![语义说明](./assets/xxx.png)`**（`[]` 非空、相对路径 colocated）为主；**可选**极短场景/状态补充（见 **七**）；**不写**流程说明、整段注意事项。**不要求**设计列放置可点击的页面 URL。详见 **七 → 模板**。
5.1. **交互列写作范围**：按 **「五 → 交互列写作清单」** 核对模块里出现的控件类型（文案 / 输入框 / 选项 / 联动 / 删除 / 列表 / 筛选 / 弹窗 / CTA），**按需挑关键项写**——不是清单上每条都填，行业默认 / 平台惯例 / 看图即知 / 已被定稿文案蕴含的**不写**。清单外内容（loading / 空态 / 权限态 / 分页等）默认不写。**全局默认**：弹窗再次打开默认不回显，无须每次声明。
5.2. **交互列叙述结构**：按 **「五 → 交互列叙述结构」** 自上而下五段（**入口 → 页面级行为 → 表单内容区 → 浮窗 → 末尾操作**）；每个字段一条 bullet（**字段骨架**），**前端计算字段必须显式标注** `前端计算：<公式>`。**未保存提示**等正式交付项**不得**因「Demo 没实现」略写。
6. **截图 / 开页**：**先「七 → 启用检测」**；已配置 **Chrome DevTools MCP** 则**固定用它**；连不上先 **「七 → profile 重试」**，仍失败再备选浏览器。**全套规则见第七節**（两阶段：**探索**用 `take_snapshot`+`click(uid)` 理解页面；**入库**用 `evaluate_script` 合并构造状态 + 视口 PNG + rect 裁切；67% 缩放**同 Tab 仅首图做一次**；禁 `take_screenshot(uid)` / 100% / `style.zoom` 与页缩放混用）。若本机有可运行 Demo，导航地址以终端 origin + 路由为准，**禁止**猜端口、猜 path（见 **四**）。
7. **写回粒度**：最小 **单行 / 单 block**；默认只改 `交互` / `逻辑`（见 **四**）。
8. **逻辑列**：无页后规则则**整格留空**（不用「无」「—」）。详见 **五 → 逻辑列**。
9. **正文语言**：简体中文；`block` 与 `.cursor/rules/prd-writing-guard.mdc` 一致。
10. **禁止占位符**（摘要）：`交互` / `逻辑` 不用 **N**、**X**、**C 端 / B 端**、**YYYY-MM** 等代指业务概念；用可读中文；端侧写 **顾客端 / 商家后台**。细则见 **prd-writing-style**。
11. **初稿即简洁**（摘要）：第一次落笔就控制交互/逻辑密度，**不**两侧同义重复；能 **详见 ×.×.×** 则不重写；**不是**「先写冗稿再删」。**章节号引用统一写 `**多段号**`**（如 **`详见 **2.1.5**`**）——前端会自动识别为可点跳转锚点；不得为孤立章节号纯视觉加粗，不得写自定义锚点语法。细则见 `prd-writing-guard`「章节号引用与跳转锚点」与 **prd-writing-style**。
12. **待确认、行业通行、禁用「以现网为准」**：见 **prd-writing-style** 与 **四**。
13. **`block:paragraph` 多行**：同一段落内**直接换行**、**行间不留空行**。详见 **六 → paragraph**。
14. **图片 Markdown 路径与 alt（强制）**：新增图片走 colocated 模型——磁盘 `pages/<slug>/assets/xxx.png`，正文 **`![语义说明](./assets/xxx.png)`**，`[]` 内非空。**禁止**新写 `/prd/xxx.png` 绝对路径（迁移期遗留旧引用仍可读）。细则见 **五 → 图片 Markdown alt** 与 `prd-writing-guard.mdc`。
15. **格内图片与列表（强制）**：`./assets/` 图**单独成行**，行首即 `![`；**禁止** `  - ![…](…)`、`1. ![…](…)` 等列表前缀后只跟一张图。细则见 **五 → 格内图片与列表** 与 `prd-writing-guard.mdc`。
16. **正文禁入内容**：工程路径/路由/快照壳、版本对齐声明、Agent 工作流程、本地存储 key / state 结构 / 代码标识符 / mock 标记、渲染实现指导（CSS 定位等）、组件标准交互教科书——**一律不入 PRD 正文**。**另**：禁止 **演示环境 / Demo / 本机 / 本地（开发环境）/ 联调** 等**非正式交付**语境锚点；需求范围用产品语言表述。细则见 `prd-writing-guard.mdc`「正文禁入内容」（含第 8～9 条）与 **prd-writing-style**「语气与可读性」「不写的内容」第 6–8 条。
17. **语气**：交付研发、可评审；**口语化短句、好懂**，避免论文腔与堆砌黑话——见 **prd-writing-style → 语气与可读性**。

## 〇·二、文档自动创建

用户要新 PRD 而尚无对应文档时，**主动创建**：

1. `GET http://127.0.0.1:6001/__prd__/list-docs` 查看列表。
2. 需新建则 `POST http://127.0.0.1:6001/__prd__/create-doc`，body：`{ "name": "<文档主文件名>" }`（不含 `.md`）。命名规则同 `shared/prd-filename-sanitize.js` 的 `toSafeDocBaseName`（中文/英文/数字及 `.` `_` `-`，禁非法字符与保留名等）。
3. 返回 `{ ok, slug, title, mdPath }` 后读 `mdPath` 对应 `.md` 写入。

API 在 `127.0.0.1:6001`；可用 Shell `curl -s -X POST … -H 'Content-Type: application/json' -d '{"name":"…"}'` 调用。

## 二、数据源优先级

1. 用户当前消息与明确要求。
2. 业务源码与运行页（嵌套默认 `../`；多根工作区为其他根或用户指定路径）。
3. 补充文档、`docs/`、现有 PRD 正文。
4. `annotations.json`：仅当用户说「按标注来」或需圈定局部时。

**冲突**：可见 UI / 前端状态 → 以运行页与源码为准；隐藏逻辑 → 自然语言与补充文档；Demo 与文档可见行为冲突 → Demo 为准；隐藏逻辑冲突 → 先确认用户。

## 三、默认触发与执行流程

**触发：**

- 「写 PRD」「按套路写」→ 先过 **〇·一**，读当前激活 `.md`，以本地 Demo 为主写 **`交互`**；有页后规则再写 **`逻辑`**，否则逻辑列留空；**默认**为含交互的新模块**截图并补设计列**（**七**）。
- 「补截图 / 设计列」→ 走 **七**。
- 「按标注来」→ **八**。
- 用户给出新的 Demo 路径或地址 → 以该源为准。

### 执行流程：了解全貌再动笔（强制）

修改或新增 PRD 正文前，**必须**依次完成以下四步；`prd-writing-guard.mdc` 有同主题的精简版。

#### 步骤 1：读全范围——划定边界

- 用户指向某标题（h2/h3/h4）或行号时，**从该标题读到下一个同级标题**——覆盖所有子标题、`block:table`（含每个 table 的行数）、`block:paragraph`、`block:mermaid` 等。
- **动笔前输出一句结构摘要**，例如：「该 h3 下有 2 个 h4、3 个 table 共 8 行、1 个 paragraph」。这既帮自身确认边界，也让用户能校验 Agent 是否读全。
- **禁止**只读目标行附近 30～50 行就开始写；若范围超过单次阅读窗口，分段读完再汇总。

#### 步骤 2：核实真实状态——看真相

修改涉及 UI 描述（交互列或设计列）时，**必须先确认真实 UI 状态**。

**信息源优先级**（按可用性依次尝试）：

1. **用户当轮提供的截图**：已摆在面前的真相，先消化——提取模块、字段、控件、状态。若截图已足够覆盖该模块主要状态，可不再跑前端，但须声明「基于你提供的截图，我观察到 xxx」。
2. **Chrome DevTools MCP**（本地 Demo 在跑时）：`take_snapshot` 拿 a11y 树理解结构；逐步交互（`click(uid)` / `fill(uid)`）发现截图未展示的状态（折叠/展开、Tab 切换、浮层等）。工具优先级与启用检测见 **七**。
3. **cursor-ide-browser**（DevTools 不可用时备选）：仍遵守 **七** 的规则。

**不涉及 UI 描述的纯逻辑修改**（如只改逻辑列的判定条件）可跳过本步。

#### 步骤 3（按需）：代码侦察——补充不可见逻辑

**触发条件**（满足任一即执行）：
- 修改涉及**逻辑列**，且多根工作区内有可访问的业务代码
- 用户明确要求「把这个模块写完整 / 写全」

**做什么**：在业务代码中搜索目标模块的组件/路由（搜组件名、路径关键词），关注：
- **条件渲染分支**——前端当前不可见的 UI 状态（某些条件才显示的组件）
- **注释与常量**——开发者标注的业务规则、枚举值
- **接口调用与参数处理**——页后逻辑的线索（过滤、计算、准入等）

**只读**业务代码，**绝不修改**（见 **零**）。纯 UI 描述更新（不涉及逻辑列）可跳过本步。

#### 步骤 4：对比判断 → 写回

带着步骤 2～3 获取的真相，回来审视步骤 1 读到的 PRD 现有内容：

- **逐行判断**：现有内容与真实状态一致 → **保留**；过时或不准确 → **更新**；缺失 → **补充**；多余（旧版残留）→ **删除**。
- **三列判断（模块级修改时强制）**：修改范围为完整 h3/h4 或更大章节时，三列都要做判断——
  - **设计/原型稿列**：现有截图是否仍反映当前 UI？需要补图/换图/还是不动？
  - **交互列**：描述是否与真实 UI 一致？字段、控件、文案有无增删改？
  - **逻辑列**：有无需补充的页后规则？还是应留空？
  - 判断是必须的，修改是按需的——确认「不需要动」也是一个合格的判断结果。
- **单行/单格小修**（用户指定了具体行和列）：只改指定范围，不强制三列判断。
- **写回格式**：尊重 `<!-- block:type -->`、cell 标记结构、图片路径格式（**〇·一**、**四**）；保存后可被前端正确渲染。

## 四、写回约束与本地 Demo（成图 / 核对 UI 用）

- 保留 `<!-- block:type -->`、cell 标记结构、图片路径格式；图片须 **`![语义说明](./assets/...)`**（`[]` 非空、相对路径 colocated）。
- **多个 `block:h1`**：允许长文档骨架（文档名 → 需求概述 → …）；勿与旧「全文仅一个 h1」混淆。
- 最小单位 **单行**；默认只改 `交互` / `逻辑`；`changeIntent='unchanged'`、`locked=true` 默认不改。**例外**：模块级修改时三列均须**判断**是否需变更（**三 → 步骤 4**），但仍只**修改**确实需要改的列。
- 简体中文。**待确认、行业通行、禁用「以现网为准」** → **prd-writing-style**。
- **大块多子模块**：`h3`/`h4` 分块，子模块各自 `block:table`，勿硬塞同一表多行（除非用户要求）。
- **PRD 设计列不要求**写入可点击的页面 URL（无线上地址、内网 Demo 时常变均属正常）。
- **若本机有业务 Demo、需要打开页面截图或核对 UI**（**七**）：  
  1. 业务项目 `npm run dev`，以**终端 Local origin** 为准（端口会变）。  
  2. 路由配置拼 `origin + path` 得候选 URL。  
  3. 用浏览器工具打开：**已配置 Chrome DevTools MCP 则固定用它**（否则 **七** 备选 Browser）；重定向以工具返回为准。**禁止**猜端口、猜 path；可从已开浏览器地址栏复制。  
  4. **注意**：PRD 站（如 `6001`）与业务 Demo（如 Vite `5173`）**不同 origin**，勿混用。

## 五、列职责

### `交互` 列

- 只写**商家后台**可见可操作：字段、控件、定稿文案（与设计列、说明一致）。
- **入口 / 导航 / 能力卡**：概括模块 + 分点写入口、点击对象、目标页（`**加粗**`）；无页后规则则 **`逻辑` 留空**，勿用逻辑列堆路由复述。
- **【】**：仅真实 **按钮 / 链接式 CTA** 用 **【】**；字段名、Tab、卡片标题等一律 `**加粗**`。**例外**：hover 定稿必须用 **【hover 文案】**（见下）。
- 输入限制（最值、默认、单位、字数）写在**交互**；待确认句式见 **prd-writing-style**。
- **枚举**：选项直接列全；勿再写「与字典对齐」等实现套话。
- **不写哪些字、先概括再分点、说明文案与元说明**：见 **prd-writing-style**。

##### hover / 说明气泡定稿（交互列 · **强制**）

- **适用**：问号 / 帮助图标 / 悬停或聚焦气泡、须写入的 **`title` 悬停句**。**不适用**：整段说明 → 用 **说明文案**，勿用【hover 文案】（见 **prd-writing-style**）。
- **固定写法**：`- **【hover 文案】**：` + 完整句。**禁止** `:**` 紧贴后续汉字导致 markdown-it 加粗失败；**禁止** `说明（…）` 括全文。
- **示例**：`- **【hover 文案】**：用您店近30天会员进店停留做的参考（每周更新），帮您看个大概：晚一点再弹窗，还有多少会员可能还在页面上，方便调「弹窗首次弹出时间」。仅供参考，非实时。`

#### 表格单元格内「交互 / 逻辑」列：换行与子项列举（强制）

列举子项 → **交互与逻辑同一版式**：多条并列则**一条 `-`（或 `1.`）一条意**；**禁止**顿号、分号、一条 bullet 塞满多字段/多规则。层级用 **`  - `**。加粗标题后空行再 bullet。极窄例外：全格一句极简枚举且无按钮名时可短句；一旦出现字段名或【按钮】须改为一项一行。设计列不按本节拆 bullet（见 **七**）。

#### cell 标记格式（表格语法 v2）

表格使用 cell 标记格式，**废除** GFM 管道行和独立 `<!-- row:N -->` 标记。结构：`<!-- block:table cols="列1,列2,..." -->` → `<!-- cell:rN:列名 -->`。`block:table` **无 id 属性**，只有 `cols`。每个 cell 标记自带行号 `rN`（N 从 1 递增），Agent 可 `grep "cell:r2:交互"` 精准定位。格内用**原生 Markdown**：段落间空行分隔、列表直接 `- ` / `  - `、图片 **`![语义说明](url)`** 独立一行。**禁止格内放 mermaid / mindmap（强制）**——流程图、时序图、状态图、逻辑图、脑图等**一律**抽到表格外作为顶层 `<!-- block:mermaid -->` / `<!-- block:mindmap -->`，cell 内只能用一句话引用（详见 **六 → Mermaid 图表 block**）。**废除** `<br>` 换行、`:::mermaid:::` / `:::mindmap:::` 包裹语法。Parser 仍兼容读取旧 GFM 管道行格式（打开→保存自动迁移）。详见 `prd-writing-guard.mdc`。

#### 交互列 Markdown 写法规范

（本节含 **表格图片** 与单元格格式。）

格内叙述用**原生 Markdown 段落**（空行分隔）。区块 `**标题**` 后空行再 bullet。**表格图片**：须**独立成段**（空行分隔），**禁止**行内图文混排（飞书同步与解析会丢行内图）；勿在反引号代码 span 内写完整 `![…](...)`。**`[]` 内须有语义化说明**（见下节）。

##### 格内图片与列表（禁止）

与飞书能力对齐：**不支持**「有序/无序列表行上整行只有一张图」的写法；本仓库编辑器侧亦**不以列表项语义**展示纯图（产品收敛为独立图片块）。源文须直接避免下列形式：

- **禁止**：`  - ![语义说明](./assets/…)`、`    - ![](./assets/…)`、`1. ![](./assets/…)`、`a. ![](./assets/…)` —— 即 **列表标记（`-` / `*` / `+` / `数字.` / `字母.`）+ 空格 + 整行仅一张 `![…](…)`**。
- **应写**：图**单独一行**，行首即为 `![语义说明](./assets/…)`；若需承接上文 bullet，在列表末与图之间**空一行**再写图行。
- **若需「先分点、再逐张附图」**：说明用列表；每张图仍**单独一行** `![…](…)`，图行前**空一行**起新段，**不要**给图行加列表前缀冒充子项。

##### 图片 Markdown alt（强制）

- **写法**：`![语义说明](./assets/xxx.png)`（colocated 相对路径）。**禁止**空 alt：`![](./assets/xxx.png)`。**禁止**新写 `/prd/xxx.png` 绝对路径（兼容期遗留旧引用仍可读）。
- **语义说明写什么**：一句内说清**画面主体**——模块或页面区域 + 关键界面状态（如「会员弹窗-折扣配置-未选会员类型」）。可与 `pages/<slug>/assets/` 文件名呼应，**不须**与文件名逐字相同。
- **适用范围**：表格 **设计/原型稿** 列、段落 block、凡引用图片**均适用**。
- **存量文档**：旧文可能仍为 `![](...)`；迭代该格或补图时**顺手改为**带 alt；新写**一律**带 alt。
- **措辞习惯**：见 **prd-writing-style**（与硬协议不冲突时）。

**版式参考**：仓库正文 **2.1.4**；需完整示例时对照该节。

#### 交互列写作清单（按控件类型 · 写关键项即可）

> 本清单按出现的**控件 / 场景类型**，列出**可能涉及的关注项**——是**备查表**，不是"全填表"。实际写时**只挑关键的、非默认的、容易被开发误解或遗漏的**项写；行业默认 / 平台惯例 / 看图即知 / 已被定稿文案蕴含的**不写**。清单外的内容（loading / 空态 / 权限态 / 网络异常 / 分页默认值等）**默认不写**，个别需求需要时由用户在该需求中显式说明。

##### 取舍原则（先看这里再翻清单）

- **写关键的，不写默认的**：默认行为（如「文本输入框默认单行 / 失焦校验」）、平台惯例（Esc 关弹窗、点击遮罩关闭）、组件库默认（输入框默认有清空按钮）等**不写**。
- **写非显然的，不写一眼可见的**：界面上一眼可见的标签 / 占位（截图能看到的）**不写**；hover、校验、操作后才出现的、变量动态拼出的文案**才写**。
- **直白简短**：每个关注项**一句话**说清楚——不堆同义词、不绕弯。能用「正整数 1～99」就不用「请输入大于零且不超过九十九的整数」。
- **以字段为骨架**：每个字段独立成条，下挂该字段的相关项；**禁止**一条 bullet 横扫整张卡（同 prd-writing-style「初稿即简洁」第 6 条）。
- **判定 vs 撰写**：清单是用来**判定要不要写**——判定后**写不写、写多少**由是否关键决定。

##### 控件类型清单

> 每条都是**按需**——出现这类控件时**判定是否需要写**，关键就写、默认就略。

**文案**（只写**交互后才出现**的文案与**含变量**的动态文案；静态固定标签 / 提示文字看图即知，不写——同 prd-writing-style「不写的内容」第 6 条）

- **hover / 帮助气泡 / 浮层文案**：写。按 hover 定稿格式（**`- **【hover 文案】**：`** + 全文）。
- **表单校验红字提示文案**：写。触发条件 + 定稿句（如「未填写时显示「请输入活动名称」」）。
- **操作后才出现的文案**：写。Toast / 确认条 / 状态变更横幅等，触发动作 + 定稿句。
- **含变量的动态文案**：写。占位变量 + 来源（如「**已匹配 {当前会员数} 人**」，`{当前会员数}` 来自后台实时计算）。

**输入框**

- **placeholder**：截图看不出 / 是定稿句时才写；与字段名同义、看图即知 → 略。
- **默认值**：有默认才写（值或来源）；无默认 → 略，不必写「无默认值」。
- **输入限制**：有限制才写（字数上限、整数 / 小数、取值范围、单位）。
- **必填 / 非必填**：与默认相反时写（团队默认必填 → 仅非必填字段需注明，反之同理）。

**选项控件**（单选 / 多选 / 开关 / 下拉）

- **默认选中 / 默认值**：有默认才写。
- **选项枚举**：基本都要写——除非截图能完整列出且数量极少。

**多控件之间的联动**

- 有联动才写：A 改变后，B 的 **值 / 显示 / 灰显 / 清空 / 取值范围** 如何变。**写在触发字段下**，不是被联动字段下。

**删除按钮**

- **是否二次确认**：直接删除 / 弹确认弹窗——这一项基本必写，默认行为容易被开发理解错。
- 若有确认弹窗：标题、文案、按钮名。

**列表 / 卡片展示**

- **展示字段**：前端展示哪些字段（与接口字段对齐）。
- **默认排序**：按哪个字段、升序 or 降序。

**筛选器**

- **每个筛选项 + 备选范围 / 数据来源**：可选值从哪来（枚举 / 接口 / 字典）。
- **是否多选、默认值**：与组件默认行为不同时写。

**弹窗（选择器 / 配置弹窗）**

- **选中后回显**：回显到主面板的哪些字段。
- 再次打开是否回显 → **默认不回显**（见下方「全局默认约定」）；要回显才写。

**按钮 / CTA**

- **点击后行为**：跳哪个页 / 弹什么 / 显示什么 / 隐藏什么——这一项基本必写，否则 CTA 没意义。

##### 全局默认约定（无须每次重复）

- **弹窗再次打开是否回显已配置项**：**默认不回显**。除非交互列显式写明「再次打开时回显 xxx」，否则按不回显处理。
- **必填字段与保存按钮**：默认行为是「必填项未填完 → 保存按钮 disable」；写清字段必填即可，不必另起一条说「不填则禁用保存」。

##### 显式不入交互列的内容（默认不写）

下列**不视为本仓库 PRD 交互列的一般规范**，由界面规范、组件库或后续单独评审承载；个别需求确需说明时由用户在该需求中显式提出：

- loading / 空态 / 错误态 / 网络异常态
- 权限态（无权限隐藏 / 置灰）
- 分页默认值（页大小、起始页等）

#### 交互列叙述结构（按界面视觉顺序 · 强制）

> 一个模块（h3 / h4 一节）的交互列**按界面从上到下、从外到内**叙述。与「写作清单」配合——**清单**管"写什么、按需挑"；**叙述结构**管"按什么顺序、用什么骨架排"。

##### 模块叙述顺序（自上而下五段）

按以下顺序展开。模块**没有的段直接跳过**，不写"无"。

1. **入口 / 进入路径**：从哪个页 → 哪个按钮 → 弹什么 → 选哪个选项进来。一句话写清链路（示例：「优惠码管理页 → **【新建优惠码集合】** → 选择新建类型（弹窗）→ 全部商品可用码」）。仅当本节是**新页 / 新模块入口**时写；纯字段级修改可略。
2. **页面级行为**：跨字段、全局生效的行为。
   - **顶部提示语 / 横幅**：定稿句。
   - **离开 / 刷新页面未保存提示**：凡是**需要配置提交保存**的页面 / 弹窗都要写——无论本地 Demo 是否实现（Demo 只是撰写者的本地参考，PRD 是正式交付物）。
   - **跨字段联动 / Tab 切换数据保留**：如「未变更时分别存储两份数据，切 Tab 有提示」。
   - **其他页面级行为**：如进入页时的预填请求、页面级 loading 等。
3. **表单 / 内容区**（按视觉从上到下）：界面上的卡片 / 分区按视觉顺序逐段写；每段内的字段也按视觉顺序逐条写。每个字段独立成条（见下方「字段骨架」）。
4. **浮窗 / 子弹窗 / 详情面板**：作为**独立段**——由本模块某个字段或按钮触发的悬浮内容，单独一段写清展示内容、文案、tab、字段。
5. **提交 / 保存 / 取消等末尾操作**：模块末尾段，写底部按钮的点击行为。
   - **提交 / 保存**：loading 交互、成功后的跳转 / Toast、失败处理（有特殊处理才写）。
   - **取消 / 关闭 / 返回**：跳到哪 / 关闭什么 / 是否带未保存提示。

##### 字段骨架（每个字段一条 bullet）

每个字段写成一条独立 bullet：

- **字段名加粗** + 必要时括号注**单位 / 模式标签**（如 **门槛（货币符号）**、**优惠金额（满额减元模式展示）**）。
- 下挂 `  - ` 子项，**只放该字段的相关项**，建议顺序（有则写，无则跳过）：
  1. **联动条件**：在什么场景 / 模式下显示（如「选择满额减元时显示」）。
  2. **数据来源 / 预填**：如「后端提供初始赋值」「进入页面时请求后端预填」。
  3. **默认值 / 默认文案**。
  4. **输入限制**：可再 `    - ` 子级展开（如下挂「正整数」「下一级金额 ≥ 上一级」）。
  5. **hover**：按 hover 定稿格式。
  6. **前端计算**（如有，独立一行）：见下节。
  7. **其他**：必填、特殊行为。

**禁止**：把多个字段挤同一条 bullet 用顿号 / 分号串起来（同 prd-writing-style「初稿即简洁」第 6 条「以字段为轴」）。

##### 前端计算字段必须显式标注（强制）

凡**前端拿数据后再算了展示**的字段，必须用 **`前端计算：<公式>`** 一行明确写出——这是**产品 / 前端 / 后端三方分工的关键边界**，不写清楚开发会反复确认。

**写法要求**

- **公式**：用字段名 / 自然语言，不用代码符号（如「优惠金额 / 门槛 × 100%」，**不写** `discount = price / threshold`）。
- **取整 / 四舍五入 / 单位**：必写（如「四舍五入展示整数折扣，例如 14.78% → 15%」）。
- **参与计算的字段**：哪几个字段算来的；有歧义时注明哪个是后端推荐、哪个是前端用户输入。

**示例**

```md
- **对应折扣**（满额减元模式展示）
  - 联动：满额减元模式下显示
  - 前端计算：优惠金额 / 门槛 × 100%
  - 四舍五入展示整数折扣，例如 14.78% → 15%
```

##### 边界提示：本地 Demo ≠ PRD 交付物（强制）

本地 Demo 是 PRD 撰写者的**参考实现**，不是 PRD 的边界——PRD 必须按"正式交付给开发"的标准写。Agent 在写交互列时**不得**以「Demo 没实现」为由略写下列项：

- **未保存提示**：Demo 没做，PRD 仍要写（凡是需要提交保存的页面）。
- **数据来源**：Demo 用 mock，PRD 要用产品语言写真实来源（如「来自后台店铺商品库」），**不**夹带 mock / 接口名 / state 字段。
- **定稿文案**：Demo 用占位串，PRD 要写定稿文案；尚未定稿则按 prd-writing-style「待确认」句式写。
- **完整状态**：Demo 只展示主路径，PRD 要按写作清单覆盖联动 / 校验 / 提示 / Toast。

与 `prd-writing-guard.mdc` 第 8 条配合：Demo / 本地 / 联调环境锚点**不进入 PRD 正文表达**——Demo 只服务 Agent 与撰写者本地核对 UI。

### `逻辑` 列

- 只写页面上**看不到**的规则：判断、计算、过滤、流转、准入等。纯展示/入口且无页后规则 → **留空**，勿复述交互。

#### 逻辑列禁写（非产品定义的「逻辑」）

下列勿为撑篇幅塞进 **逻辑** 列——属实现惯例、设计说明或与 **交互** 重复，**不是**须单独成文的页后业务规则：**设计与工程实现细节**（如 design token、代码映射）；**交互**已写清取值仍写「非法回退」；**枚举与界面一致**类 → 放交互；**本地存储 key / 内部 state 结构 / mock 标记**（如 `localStorage` 键名、state 字段枚举、「刷新可复现，非线上接口」等运行态说明）——属开发联调信息，不入需求。

**留空与导航类模块**：仅导航/能力卡、无频控准入等页后规则时，**逻辑格空白**（勿填「无」）；路由实现细节默认不写 PRD；必要导航约定**合并进交互一句**。换行规则与交互列相同（**上节**）。

#### 选择器弹窗 / 多选面板（逻辑列只补三项）

交互：可见操作、列表、「全选/清除」等。**逻辑**只写：1）**后台隐藏过滤**（界面上看不全来源时）；2）**特殊筛选**（无法从操作推断时）；3）**排序**（依赖后台且非界面顺序说明时）。禁重复交互已写的枚举与通用弹窗行为。

## 六、Block、章节与变更语义

**变更用语**（全新 / 原页新增 / 迭代 / 沿用现状）与**小节标题命名习惯**：见 **prd-writing-style**。

### 纯逻辑不用三列表格

无界面可配、无可截之图的全局规则 → `###` + `paragraph` 或 `mermaid`，勿硬塞三列表。

#### `paragraph`：同一段落内多行

同一块内多行：**直接换行**，勿行尾 `\`；**行间不留空行**（空行会拆块）。

#### Mermaid 图表 block（流程图 / 时序图 / 逻辑图等 · 仅顶层）

`<!-- block:mermaid -->` + `` ```mermaid `` 围栏，**只能作为顶层 block 独立成段**。视图模式与宽度由编辑器写入 `.meta.json`（切换视图后应立即落盘），**默认偏图表展示**即可。

**禁止放在表格单元格内（强制）**：交互 / 逻辑 / 设计列**任意 cell 内一律不得**写 `` ```mermaid `` 围栏（流程图、时序图、状态图、逻辑图、ER 图等**全部 mermaid 图表**均含在内）。需要画图时**把图从表格里抽出来**，作为**独立的顶层 `<!-- block:mermaid -->`** 放在该模块的表格之外（通常在表格上方或下方紧邻位置），表格内**用一句话引用**（如「流程图见下」「详见 **2.1.5** 上方流程图」）。**废除**旧 `:::mermaid:::` 包裹语法（Parser 仍兼容读取，但**不得**新写）。

#### 思维导图 block（脑图 · 仅顶层）

#### 常见文档骨架与表格绑定（`buildTableBindings`）

### 工具优先级与禁则

1. **先启用检测**：打开 Demo / 截图 / 看结构前，确认 **Chrome DevTools MCP**（如 `user-chrome-devtools`）已在 Cursor **Tools & MCP** 启用或工具目录存在 `navigate_page`、`take_screenshot`、`evaluate_script` 等。

3. **未配置** → 直接用 **cursor-ide-browser**（仍 67% + 裁切）。

5. **入库截图**：页缩放**仅 67%**；**禁止** 100% 入库、**禁止** `take_screenshot(uid)` 作为模块成图、**禁止** `document.documentElement.style.zoom` 与浏览器缩放混用。  
6. **唯一标准**：**视口** `take_screenshot`（无 uid）+ **`getBoundingClientRect`（或 Browser：`browser_get_bounding_box` 快照 ref）** + **PNG 像素与视口 CSS 宽高比例**本机裁切 → **`pages/<slug>/assets/`**。

### 启用检测（Chrome DevTools MCP · 强制执行前）

在**打开本机 Demo**、**看结构/文案**、**设计列入库截图**之前，先确认已配置并启用 **Chrome DevTools MCP**（常见名 **`user-chrome-devtools`** / **`chrome-devtools`**，以 **Cursor → Settings → Tools & MCP** 为准）。**检测方式**（任一种即可）：**(1)** Settings 列表中服务已启用；**(2)** 工作区 **`.cursor`/MCP 工具目录**（如 `mcps/user-chrome-devtools/tools/`）下存在 `navigate_page`、`take_screenshot`、`evaluate_script` 等工具描述 JSON。

- **已配置且可用**：**固定**用该 MCP 完成打开、导航、快照、视口截图、`evaluate_script`；**不得**首选其它浏览器 MCP。
- **未配置 / 未启用**：直接用 **`cursor-ide-browser`**，仍遵守 **67% 标准成图法**。
- **已配置但连不上**：**勿立刻降级**；先 **profile 占用重试**（见下），仍失败再 Browser，或按 **`.cursor/rules/prd-screenshot.mdc`** 标「截图待补」。
- **用户明确要求**只用某一浏览器 MCP：服从当次指令，但仍须 **67%** + **视口 PNG + rect 裁切**（或等效）。

### 优先：Chrome DevTools MCP（设计列默认）

通过「启用检测」后，设计列真实截图**必须**用 **Chrome DevTools MCP**（名称以本机 Tools & MCP 为准）。工具名随版本变化，常见包括：`list_pages`、`new_page`、`select_page`、`navigate_page`、`wait_for`、`press_key`、`take_snapshot`、`take_screenshot`、`evaluate_script`、`click` 等。

### profile 占用重试（Chrome MCP 典型报错）

报错含 `chrome-devtools-mcp/chrome-profile`、browser already running：**同一 user-data-dir 已被占用**。关 MCP 打开的 Chrome → 结束占用该 profile 的进程（例：`pkill -f "user-data-dir=.*/chrome-devtools-mcp/chrome-profile"`，勿 `killall` 误杀日常 Chrome）→ 重试 MCP。仍失败与禁止额外自动化栈等见 **`.cursor/rules/prd-screenshot.mdc`**。

### 67% 标准成图法（两阶段 · 强制）

截图分**探索**和**入库**两阶段——探索用于理解页面、发现可截状态；入库用于高效产出 67% 规范图。

#### 探索阶段（确认要截什么）

目的：Agent 理解页面结构、逐步交互发现值得入 PRD 的状态与截图选区。  
本阶段**不产出入库 PNG**；可在任意缩放下操作。

1. `list_pages` / `new_page` / `select_page`：打开业务 Demo URL（**四** 得真实地址；拒绝则先起 dev）。  
2. `wait_for`：关键文案出现。  
3. `take_snapshot`：拿 a11y 树与 uid，理解页面当前状态。  
4. `click(uid)` / `fill(uid)` / 逐步交互：发现交互细节（如展开折叠、切 Tab、触发浮层等）；每步可再 `take_snapshot` 确认 DOM 变化。  
5. **产出**：一份**截图计划**（心中或注释里）——列出本模块要截哪几张图、每张图需要什么 UI 状态、目标容器的 CSS 选择器。

#### 入库阶段（高效成图）

目的：对探索阶段确认的目标状态，按 67% 规范快速出图。

**A. 缩放（仅首张图做一次）**

1. **页缩放 67%**：`Meta+0`/`Control+0` 后连续 **4 次** `Meta+-`/`Control+-`；地址栏显示 **67%**。  
2. **缩放复用**：同一 Tab 内后续图**跳过**缩放步骤——Chrome 页缩放是 **Tab 级持久**，不刷新/不整页跳转则不变。仅 `navigate_page` 跳转或手动刷新后才重做。

**B. 每张图三步循环**

3. **`evaluate_script` 一次完成**：将该张图所需的全部状态构造（切 Tab、展开折叠卡、点击按钮、填值、失焦等）+ `scrollIntoView` + 返回 `getBoundingClientRect()` 与 `innerWidth`/`innerHeight` **合并到一次脚本**。  
   - DOM 交互用 `querySelector` + `.click()`；React 受控输入用原生 `HTMLInputElement.prototype.value` setter + `dispatchEvent(new Event('input', { bubbles: true }))`；`.blur()` 触发失焦。  
   - 每步交互后 `await new Promise(r => setTimeout(r, 60~100))` 等 React 重渲染（根据组件复杂度调整；含 `queueMicrotask` 的逻辑可能需要略长）。  
   - 浮层与主容器分离时对多块 rect **求并集**（可 padding）。  
   - （可选）注入 `<style>` 隐藏 Demo-only 控件；`localStorage` 调数据出目标态；**不得**改业务仓库。  
4. **`take_screenshot`**：不传 uid，PNG 整视口。  
5. **裁切**：`sx = pngW/innerWidth`，`sy = pngH/innerHeight`；`crop = floor(rect * scale)`，钳制在图内；`sips`/`PIL` 写入 **`prd-standalone/pages/<slug>/assets/xxx.png`**（slug 取当前激活文档；写入后正文用 `./assets/xxx.png` 引用）。  
6. **下一张图**：重复步骤 3～5；**不重复**缩放，**不重复** `take_snapshot`。

**效率对比**：每张入库图 = **1 次 `evaluate_script` + 1 次 `take_screenshot` + 1 次本机裁切**（3 次调用），而非旧流程的 `take_snapshot` → `click` → `take_snapshot` → `evaluate_script`（rect）→ `take_screenshot`（5+ 次调用）。

**说明**：`take_snapshot` 在入库阶段**仅当** `evaluate_script` 内选择器无法确认目标时作为后备；`fullPage: true` 仅长页需要且仍在 67% 下。**Cursor Browser**：67% → 视口 `browser_take_screenshot` → `browser_get_bounding_box(ref)` → **同公式裁切**；**勿**把快照 `ref` 当作 `browser_take_screenshot` 的 CSS `ref`；可用 `browser_resize` 减灰边。

### 选区与画幅

- **默认（模块行）**：表格行多对应 **h4 下一块功能**；截图优先包住该模块在页面上的**容器面板 DOM**（整张配置卡、分区 wrapper 等），**不要**顺手整页、**不要**只截单行/孤立图标（除非该节仅描述该控件且用户要求）。
- **用户或 DevTools 给出矩形**：若提供 DOM Path、`getBoundingClientRect` 或与组件对齐的框，视为模块根容器范围；在 **67%** 下按 **「入库阶段」** 步骤 3～5 裁切；**禁止** `take_screenshot(uid)`。
- **DOM 定位（示例）**：可在 **67%** 下对 **`[role=region][aria-label=…]`**、**`.moc-editor-shell-alert-bundle`** 等取 `getBoundingClientRect` + 视口 PNG 比例裁切（与业务实际选择器以 Demo 为准）。
- **绝对定位浮层 / 下拉**：主容器与已展开子面板（如 **`.moc-prereq-hover-wrap--open .moc-prereq-hover-panel`**）分离时，对多块 rect **求并集** 再裁切（可 **padding**，如 6px）。
- **`cursor-ide-browser` 的 `ref` 易错**：快照里的 **`ref`（如 e71）** 与 **`browser_take_screenshot` 的 CSS `ref`** 不是同一语义；**勿**把快照 `ref` 当截图目标。可靠做法：**视口** `browser_take_screenshot` + **`browser_get_bounding_box`（快照 ref）** + 同公式裁切。
- **整页 / 壳层（例外）**：仅当本节明确是整页结构、编辑器壳、路由级索引时，才用视口或壳+主区级画面。
- **留白验收（模块图）**：以**该节模块容器**为主角，面板外留白在宽或高任一侧不宜明显超过约 **5% 画幅**；超宽视口可先 **`browser_resize`**（常见 **1280–1680** 量级）再截，或事后裁灰边**勿伤业务 UI**。**`fullPage: true`** 仅长页需要；壳层索引优先视口 + 收窄宽度。
