# PRD 内容润色（prd-polish）

> 只改**写法**，不改**内容含义**。不跑前端、不查代码、不截图。

---

## 何时用

- 用户说「优化写法」「精简一下」「过一遍规范」「润色」等。
- 目标是让现有 PRD 更干净，而非重写或补写。

## 何时不用

- 需要**新写模块 / 补内容 / 改交互描述**→ 用 `@prd-spec` + `@prd-writing-style`。
- 需要**截图 / 补设计列**→ 用 `@prd-spec`。

---

## 流程（三步）

### 1. 读目标范围

读用户指定的区域（行号、标题、或截图对应的 block）。**不要求**读到同级标题闭合——只读要优化的部分即可。

### 2. 扫描 → 标记问题

逐行过以下两张清单，标记需要改的地方。

#### 清单 A：正文禁入内容（删）

对照 `prd-writing-guard.mdc`「正文禁入内容」，发现即删（含第 8～9 条）：

1. **Agent 工作流程**：截图怎么裁、缩放比例、对话框步骤
2. **工程坐标**：项目路径、路由、快照壳名称、Demo URL
3. **版本对齐声明**：「与 xxx 快照一致」「以 xxx 实装为准」
4. **代码标识符 / state / mock**：变量名、组件名、localStorage key、迁移函数名、「刷新可复现，非线上接口」
5. **页面位置类工程话术**：「本模块位于 xxx 与 xxx 之间」、DOM 层级描述（与 **`prd-writing-guard`** 第 5 条一致）
6. **渲染实现指导**：CSS 定位策略、z-index、溢出处理
7. **组件标准交互教科书**：click/Enter/Space 展收、Chip 形态、箭头暗示等平台惯例
8. **演示 / Demo / 本地语境**：**演示环境**、**Demo**、**本机**、**本地**（开发机语义）、**联调**、**快照壳** 等绑定非交付环境的锚点——改为产品侧说法（**商家后台**、**本期**、**配置页** 等）；**禁止**「演示环境 · YYYY-MM-DD」式环境标签。**例外**：**本地上传**、**本地文件** 等产品功能词可保留（见 **`prd-writing-guard`** 第 8 条）
9. **语气**：删论文腔、删堆砌黑话；保留含义，改**口语化短句**（见 **prd-writing-style → 语气与可读性**）

#### 清单 B：交互列不写的内容（删或精简）

对照 `prd-writing-style`「不写的内容」8 条：

1. **截图已表达的**：结构、布局、控件位置
2. **设计稿职责的**：元素顺序、间距
3. **开发实现细节**：已隐含在枚举里的规则
4. **顾客端条件分支**→ 归逻辑列
5. **写作元说明**：「本段侧重」「与某节互补」
6. **静态固定文案**：界面一眼可见的标签——只留动态文案和 hover 文案
7. **通用交互模式与组件惯例**：Esc 关闭、点遮罩关闭、标准模态自解释按钮、下拉/Chip/箭头等 Web 惯例
8. **渲染实现指导**：CSS 定位等

#### 清单 C：格式修正（改）

- **图片 alt**：`![](/prd/…)` → `![语义说明](/prd/…)`
- **设计列版式**：先图后文；状态说明 / 场景预览放图下方；冒号后多项必须换行
- **换行密度**：多条规则一条一行，禁堆分号长句
- **hover 定稿**：`- **【hover 文案】**：` + 全文
- **格内图片**：图单独成行，禁 `- ![…](…)` 列表前缀挂图
- 保留 `<!-- block:type -->` 和 `<!-- cell:rN:列名 -->` 标记不动

### 3. 修改 → 写回

- **最小改动原则**：只改写法，不改产品含义。
- 删掉的噪音如果承载了有用信息（如某个配置的默认值），保留信息、去掉噪音外壳。
- 写回时保留 block 标记、cell 标记、图片路径格式。

---

## 不做的事

- **不核实 UI**：不打开浏览器、不跑 Demo、不用 DevTools。
- **不查代码**：不搜业务源码、不做代码侦察。
- **不截图**：不产出 / 不替换设计列图片。
- **不重写内容**：不补写缺失的模块、不改交互逻辑、不调整章节结构。
- **不改目标范围外的内容**。
